# SDK, CLI and MCP transport boundary

Updated 5 November 2026. Implemented: a transport slice with authored backend
tests. **Real service integration is blocked on accepted A/B interfaces.** This
document does not freeze an alternative domain contract. No real assessment has
been generated by this slice.

## Mission and delivery sequence

The owner wants one checkpoint-bound backend accessible through Python, a shell
and MCP, with the same results for later frontend consumption. The boundary must
not turn a successful invocation into rule PASS or decision clearance.

- Now (implemented): bounded JSON, trusted operation/run grants, shared dispatch,
  JSON CLI errors and official MCP stdio discovery/invocation tests.
- Next (blocked): bind the accepted A validators and B service, resolve stored
  references, validate outputs and test parity over the real persisted core.
- Later (deferred): test individual host installation/capture/gates; frontend and
  independent quality evaluation remain outside this lane.

Owned code is `continuous_verification/sdk.py`, `cli.py`, `mcp_server.py`, and
`tests/test_continuous_interfaces.py`. No shared launcher, dependency lock or
`__main__.py` has been added. Reverting these owned modules removes the transport
slice; it creates no storage, migrations or capture state.

## One operation vocabulary, provisional backend seam

`Client(backend=None, access=None).call(operation, request)` accepts an inline JSON
object with an explicit `run_id`. The **provisional** backend method is
`execute(operation, request) -> dict`. It must validate the accepted operation
schema, authorize all referenced objects and call the real service. The current
wrapper validates JSON shape and size, not A's domain schema. It does not call
A's pure verifier directly or permit clients to supply trusted coverage/policy.

| Operations | Trusted permission |
|---|---|
| register_run, ingest_events, checkpoint | collect |
| verify | verify |
| acknowledge_feedback | feedback |
| get_assessment, get_evidence, get_run_state, list_events | read |

`Access(frozenset(permissions), frozenset(run_ids))` is injected by trusted host
code; both sets default empty. Model JSON cannot grant permissions or run scope.
This local allowlist is not remote authentication or complete object-level
authorization. In particular B must reject a permitted run combined with an
assessment/evidence/checkpoint ID belonging to another run. Collector permissions
cannot be inferred from verify or read permissions. Acknowledgement permission
does not establish feedback inclusion or corrective action.

Success is `{"ok": true, "result": <unchanged backend object>}`. `ok` only reports
invocation success. Readiness/errors inside an assessment, per-rule findings,
policy disposition, unknowns, bindings and stable IDs stay inside `result`.
The wrapper never generates IDs or rewrites a cursor. `after_cursor` and returned
cursor values in tests are opaque authored transport data, not implemented
pagination. Real cursor ordering, validity and access checks remain B/D work.

Transport/adapter failures use `{"ok": false, "error": {"code": ..., "message": ...}}`.
Codes include INVALID_JSON, INVALID_REQUEST, UNKNOWN_OPERATION, FORBIDDEN,
BACKEND_UNAVAILABLE and BACKEND_ERROR. Safe adapter errors can use InterfaceError;
unexpected exceptions become a generic BACKEND_ERROR without request contents,
tracebacks or private paths. Missing backend always produces
BACKEND_UNAVAILABLE on a well-formed request, never an authored assessment.

Requests/results are copied finite JSON, at most 1 MiB serialized and 32 nested
levels. Duplicate JSON keys, nonfinite numbers, invalid Unicode and unsupported
Python objects are rejected. Domain/operation-specific keys, bindings and ID
formats must be validated at the A/B adapter; this slice does not claim that
validation is complete.

## CLI

```text
python -B -m continuous_verification.cli verify --request "proposal request.json"
python -B -m continuous_verification.cli list_events < event-request.json
```

All nine operation names are accepted. JSON comes from stdin or an
operator-selected UTF-8 local `--request` file. No shell commands are constructed
or executed. Use an argument array with shell disabled when launching it from
another program. A leading-dash path can use `--request=<path>`.
MCP has no corresponding file option.

Normal invocations produce exactly one JSON object on stdout; diagnostics use
stderr. Exit 0 means the backend returned a result (which can contain NOT_READY,
FAIL or HOLD), 2 means argument/input validation failed, and 3 means unavailable,
forbidden or failed backend execution. `--help` is human-readable argparse help.

The standalone command currently has no real service factory and returns
BACKEND_UNAVAILABLE. Trusted Python hosts can inject a Client through
`cli.main(argv, client=...)`. There is intentionally no CLI fixture mode or
untrusted dynamic backend import.

## MCP dependency and stdio

The optional dependency is **`mcp>=1.28,<2`**, explicitly checked at startup.
This slice uses the documented v1 FastMCP API; v2 requires deliberate migration.
Reference: [official v1 SDK documentation](https://py.sdk.modelcontextprotocol.io/v1/)
and [official stdio client example](https://github.com/modelcontextprotocol/python-sdk/blob/main/examples/snippets/clients/stdio_client.py),
checked 5 November 2026. No homegrown protocol implementation is included.

```text
python -m pip install "mcp>=1.28,<2"
python -B -m continuous_verification.mcp_server
```

Installation is optional and should use an isolated environment. The server
exposes each operation as a tool with one `request` object. Server stdout is
exclusively owned by the SDK stdio protocol; dependency diagnostics use stderr.
`build_server(client=...)` supports trusted host injection. Standalone invocation
has no backend and returns structured BACKEND_UNAVAILABLE. Missing or unsupported
SDK exits 3 before serving. No resources, arbitrary file reads, sampling/model
calls, account settings or connectors are configured. Tool names alone grant no
operation/run permission. Request fields are never resolved as server paths.

The official ClientSession initializes, lists all nine tools and invokes each
through actual subprocess stdio in the dedicated test. A temporary authored host
returns deliberately mixed NOT_READY / FAIL / HOLD test data. Another subprocess
uses the default unavailable backend. This verifies protocol and transport
behavior, **not** real verifier/service behavior. Tests also reject path-only
requests and invalid MCP argument shapes.

## Verification and risks

```text
python -B -m unittest discover -s tests -p test_continuous_interfaces.py -v
```

Observed: Python3.11 base environment: **10 passed, 1 explicitly skipped** for
missing MCP. Isolated environment with official **mcp 1.30.0**: **11 passed**,
including genuine discovery/invocation. The base skip is not an MCP PASS.
All test inputs are authored in memory or temporary files; no private corpus,
provider or model is used.

| Risk | Test evidence |
|---|---|
| Read/verify client gains capture authority or cross-run access | Denial before authored backend invocation |
| NOT_READY / rule FAIL / HOLD flattened into PASS | All-operation SDK/CLI parity and official MCP roundtrip |
| Missing service invents a successful assessment | CLI and actual default MCP return BACKEND_UNAVAILABLE |
| Malformed/oversize inputs or backend diagnostics leak | JSON limits, safe errors and invalid-result controls |
| Shell metacharacters interpreted in a request path | Actual CLI subprocess with temporary spaced/metacharacter path |
| Optional protocol dependency hidden behind a passing fake | Explicit skip without SDK; genuine SDK stdio with dependency |

No harness has been installed or validated here. Claude Code/Desktop, Codex,
Hermes, OpenClaw and TradingAgents remain candidate access routes until tested
against their actual runtime and configuration. MCP sees only its own requests;
it cannot establish whole-session capture, hidden reasoning, feedback inclusion
in later model input or a host-enforced action gate. Network service deployment
and its authentication are not implemented.

### B operation and error mapping request (proposed, not accepted)

The orchestrator reports A is **NOT ACCEPTED**: an independently reproduced
same-stream future-parent/causal-cycle packet received two PASS findings. A is
repairing that defect. Transport tests do not establish correctness of that
candidate. Wait for reviewed commit references before importing/binding it.

The following specifies the information needed from B, without prescribing a
second event/checkpoint schema. Every call has an explicit run scope. For verify,
forward the accepted A request object unchanged; do not wrap it in a competing
proposal DTO. Other operation dictionaries must be specified and validated by B
before D binds them. B may propose renames or narrower initial support; unsupported
operations must fail explicitly rather than return empty successful objects.

| Operation | Input semantics B must specify | Backend result D must preserve |
|---|---|---|
| register_run | Trusted collector's run/stream registration request; actor identity comes from host context | Stored run/stream identities and declared coverage limits |
| ingest_events | Accepted A events and target run; no trace/journal path argument | Durable receipt, idempotent duplicates and integrity/sequence conflicts |
| checkpoint | Requested registered stream prefix; never agent-issued SERVICE_ESTABLISHED state | Stored immutable checkpoint ID/revision and actual readiness/gaps |
| verify | Accepted A request, referencing stored checkpoint and registered policy | Validated A result with assessment ID/binding, readiness, findings, issues and disposition |
| get_assessment | Run plus stable assessment identity | Exact retained assessment; no re-verification or mutable overwrite |
| get_evidence | Run plus stored evidence identity and any supported bounded span | Permitted retained provenance/content; never arbitrary server file contents |
| acknowledge_feedback | Assessment/proposal binding and distinct acknowledgement identity; actor from host context | Durable acknowledgement receipt, not proof of correction or model-input inclusion |
| get_run_state | Run and any supported view/checkpoint selector | Actual ingest/projection/checkpoint state and unresolved coverage/gaps |
| list_events | Run, opaque after-cursor and bounded page limit | Stable event IDs/order, next cursor and an explicit end/snapshot boundary |

B must define cursor scope, restart stability, invalid/foreign/expired cursor
handling and whether a page is pinned or follows appends. D will neither parse a
cursor nor fabricate end-of-feed. Missing optional read support stays unsupported.
The trusted B service/adapter instance must hold its actor identity and collector
authority separately from request JSON. SDK run grants are only a preliminary
check: B must check every nested checkpoint/policy/assessment/evidence/event
reference belongs to the authorized run before any read or write.

Requested adapter mapping for review:

- Malformed operation/domain input: a safe INVALID_REQUEST failure, with bounded
  schema issues if the accepted public error contract supports them.
- Denied actor/run/object: FORBIDDEN; no referenced object contents or paths.
- Missing permitted object: an explicit NOT_FOUND failure; B defines disclosure
  policy for denied versus absent objects.
- Immutable ID/content conflict: an explicit CONFLICT failure; preserve history.
- Invalid cursor or unsupported operation: explicit INVALID_CURSOR or
  UNSUPPORTED_OPERATION failure, never an empty successful page/result.
- Missing service or unexpected execution failure: BACKEND_UNAVAILABLE or generic
  BACKEND_ERROR; no raw exception text/traceback exposure.
- A valid core response containing NOT_READY, CAPTURE_GAP, ERROR, FAIL,
  INCONCLUSIVE, HOLD or RECHECK remains the exact structured result. Transport
  `ok=true` and CLI exit 0 do not change those meanings.

These additional backend error names are proposed, not implemented/accepted B
behavior. Prefer a B-owned typed exception with an allowlisted safe code and
public details; D can translate it to InterfaceError without making B import a
transport module. Current unrecognized backend exceptions are generic
BACKEND_ERROR. The current InterfaceError envelope supports code/message only;
structured schema issues need an accepted extension rather than stringifying
private diagnostics. Agreement on this mapping and a real injected service
factory are gates before integrated parity tests.
