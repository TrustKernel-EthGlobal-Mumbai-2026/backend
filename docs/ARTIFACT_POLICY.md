# Artifact and publication policy

The default staging profile is public-safe review material: source, tests, contracts, curated research history, upstream license/provenance and authored synthetic examples. Repository visibility, source-code license and final publication remain user/parent decisions. This preparation neither publishes files nor changes those decisions.

Always exclude real credentials, private keys, wallet material, native Yahoo cookie/credential caches, virtual environments, whole cumulative spending databases, approval files and unrelated personal knowledge/chat/account exports. A private Git repository is not a reason to add credential/cache databases. Runtime cookie handling remains local to native provider requests.

Full original JSONL/SQLite, prompt/context snapshots, generated reports, canonical ledgers, third-party news/provider content and binary archives need a separate explicit artifact review and redistribution/access policy. The staging default excludes them; their work is represented in the inventory and curated summaries. Never blindly commit a directory of recorded traces because secret redaction happened once. Prompt text, URLs and source content can remain private or have separate reuse terms after token redaction.

Three useful layers are: (1) source plus safe synthetic fixtures in Git, (2) reviewed small non-sensitive derived examples with provenance, (3) access-controlled original evidence packs outside default Git. The full internal pack is a reference for exact audits, not an automatic public release. Hashes/IDs are provenance, not independent truth labels.

Path sanitization applies only to copied documentation and is listed in the export manifest with both source/staged hashes. Included implementation/test files remain byte-identical; machine-specific release packaging helpers are excluded and accounted. Raw uploaded documents, archived chat messages and screenshots are not quietly included. Draft sponsor/visual work keeps its status; event eligibility is not inferred from a fresh repository date.

The allowlist and credential-pattern scan protect this export scope, not arbitrary future Git additions. Before publication, review the manifest/diff, confirm the final lane freeze, choose license/visibility and inspect any extra files. The scanner reports path/rule/line/fingerprint only, never secret matches. No automatic push, Git initialization, account login or remote creation is part of preparation.
